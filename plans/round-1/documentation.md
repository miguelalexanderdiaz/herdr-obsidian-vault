# Round 1 - documentation audit

Role: documentation. Scope owned: README.md, docs/**, AGENTS.md, llms.txt, CHANGELOG.md, CONTRIBUTING.md.
Audited at commit f36dba0 (main). Nothing was changed except this file.

## Summary

The repo has no human or agent documentation at all (tracked files: 2 mods, sample vault, gitignore). Every
deliverable in the brief is therefore new work. The main risk for the docs is not writing, it is honesty: the code
today is macOS-only in about a dozen places (see DOC-1-2), so docs written now must state the real support
level and be re-synced after code-review and herdr-completeness land their cross-platform work. The plan is
to write the docs in round 1 against the code as it is, with a requirements matrix generated from a single
table (so round 2 only edits cells), and to treat the privacy/trust section as the first-class page because
Herdr's own install protocol requires telling the person about network use, program execution and file reads.

Verified during the audit (so the docs may state these as facts):
- `herdr-app check` passes for mods/vault and mods/vault-reader.
- `node mods/vault-reader/render/test-parse.mjs examples/sample-vault` runs clean: notes 5, errors 0, links 10,
  unresolved 1 (the deliberate `[[Missing note]]`), blocks md 15, callout 5, flow 1, math 1, mermaid 2, embed 6, code 1, query 1.
- The mods never write into the vault: the only writes are under `<app home>/data/vault/` (assets.js, render.mjs).
- Shared keys in use: `vault.list`, `vault.current`, `vault.open` (vault/main.js:7-8, vault-reader/main.js:100),
  `vault.panes` (vault-reader/main.js:103-105). Command: `vault.add` (vault/main.js:377, handled :71).

### DOC-1-3 - Privacy and trust page (what it reads, runs, fetches, stores)  (severity: high; owner: documentation)
Herdr's protocol (home AGENTS.md "Layouts and mods other people made", step 1) says an installing agent must tell the
person when a mod reaches the network, runs programs, or reads outside its folder. All three apply here, so this
page is mandatory and must be exact:
- Reads: the vault folder tree (readdir/readTextFile/watchFolder on the vault root: vault/main.js:109-150, vault-reader/main.js:48-62,243-260); Obsidian's vault list (vault/main.js:42); files an embed names, copied to cache (assets.js:115).
- Runs: `rg` (search.js), `open` (open files/links in the default app; `follow` opens any http, mailto, obsidian, file link: main.js:282), `sh -lc` through the user's login shell (assets.js:27; this executes the user's shell profile), `node` (render.mjs), headless Chrome/Chromium/Brave/Edge with a private profile `<app home>/data/vault/chrome` and `--remote-debugging-port=0` (render.mjs:85-88), `stat`, `cp`, `mv`, `sips`, `qlmanage`, `pdfinfo`, `pdftoppm`.
- Network: `fetch(url)` of every `http(s)` image in a note (assets.js:210; main.js:197): this contacts the host named in the note (IP address, user agent) as soon as the note is opened. Everything else is local: the renderer page is served from 127.0.0.1 on a random port (render.mjs:77), Chrome is started with `--disable-background-networking --disable-sync`, Mermaid runs with `securityLevel: "strict"` (page.js:16).
- Writes: only under `<app home>/data/vault/`: `cache/` (rendered diagrams, math, drawings, PDF pages, copies of vault images, downloaded web images; json sidecars), `lib/` (Mermaid + MathJax extracted from the installed Obsidian app: render.mjs:33-62), `chrome/` (headless browser profile). There is no cache eviction in the code (assets.js), so a sensitive vault leaves image/PDF renderings behind: document "delete the folder to wipe it" and flag eviction/cleanup to code-review.
- Also stored: `localStorage` key `open:<vault path>` (expanded folders); shared state keys listed in DOC-1-6.
- Never: writes into the vault, sends vault text anywhere, runs `dataview`/`dataviewjs`/`tasks` code (shown as text: parse.js QUERY set, main.js:444-446).
Change: README "Privacy" section (short) + docs/privacy.html (full table) + AGENTS.md "Tell the person before installing" checklist, all from one wording.
Verify: each bullet cites a line; re-grep for `fetch(`, `exec(`, `writeFile` at the end of round 2 to catch new behavior; compare with code-review's list.
