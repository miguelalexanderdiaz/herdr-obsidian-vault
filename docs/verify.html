Check your install

Fifteen short steps on the sample vault tell you what works on your system and what says it cannot. They are also how Linux and Windows results get reported, because those systems have not been seen running in the live Herdr app.

Use the sample vault (examples/sample-vault), never your own notes. Do not paste note text, or paths that contain your name, into a report.

The steps

StepDoExpect
1. InstallCopy both mods, then run herdr-app check on each (see Install).Both say they pass.
2. Show the panelAdd the panel block to a layout, or merge keys.json and press Ctrl+Shift+M.The Vault panel appears. Without a vault it says No vault yet.
3. Add the sample vaultChoose Add vault and pick the folder examples/sample-vault of this repository.The picker shows sample-vault. A folder without .obsidian is refused with Not an Obsidian vault.
4. TreeLook at the top level, then open projects.Folders first (attachments, projects), then Board.canvas, Feature tour.md, Flow sketch.excalidraw.md and Other note.md without their extensions. .obsidian is hidden. projects/a and projects/b are folders.
5. SearchType nested example in the search box, then tour.The first finds Feature tour.md by a line of text. The second finds it by name, first in the list. Without ripgrep you see ripgrep (rg) isn’t installed and the install command.
6. Open a noteClick Feature tour.md.A floating reader fills most of the window. A properties table shows status, project, tags, aliases and created.
7. Callouts and tasksScroll to Callouts and Tasks.Five callouts; Folded warning is closed and Open tip, foldable is open, and a click toggles them. Six tasks each show their own mark.
8. Links and BackClick Other note in the Links line, then press Alt+Left (or Backspace).Other note.md opens in the same reader. Back returns to the tour. Missing note is shown as unresolved.
9. Math and MermaidScroll to Math and Mermaid.Two inline formulas and one block formula, then a flowchart and a sequence diagram, drawn as pictures. If something is missing, one line above the note names it (Node.js, a browser or the Obsidian app) and the source stays visible. The first run takes a few seconds.
10. EmbedsScroll to Embeds.The section of Other note.md, the block, attachments/photo.png about 320 wide, the drawing Flow sketch.excalidraw.md, the first page of attachments/spec.pdf, and Board.canvas.
11. A PDFClick attachments/manual.pdf in the tree.The pages one after another. Without Poppler: macOS shows page 1; Linux and Windows show the install hint and the button Open in the default app.
12. A canvas and a drawingOpen Board.canvas, then Flow sketch.excalidraw.md.The canvas shows a group called This stage, text, note, image and link cards with arrows. The drawing is drawn clean, not as text.
13. Code and queriesScroll to the end of the tour.The Python block is shown as code. The Dataview block is shown with a shown, not run label.
14. Keep and EscPress Keep and choose New tab. Then open any note from the panel and press Esc.A tab named obsidian holds the kept note. Esc closes the floating reader.
15. Web images (optional)Add a line ![](https://example.com/x.png) to a scratch copy of the vault, never to your own.The reader bar gets Web images: on and the picture downloads, or says why not. The sample vault itself has no web image, so this step is skipped there.

A step that shows a plain message instead of the result is a pass when the message names the missing program and gives the install command for your system: that is the designed behaviour. A step that shows nothing, a blank reader or a raw error is a fail. The messages are listed on the troubleshooting page.
