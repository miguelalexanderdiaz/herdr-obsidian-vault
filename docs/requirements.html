Requirements

Only Herdr is required. Everything else is optional and adds a feature. When a program is missing, the panel or the reader says which one in plain words instead of failing.

macOS is the only OS the author uses; Linux and Windows code paths are implemented and covered by fake-platform unit tests but not run in the live app.

These programs are not bundled. For ripgrep, Node.js, Poppler and curl the mods try the bare name on your PATH, then the usual install folders of your operating system (Homebrew, Snap, Linuxbrew, Nix, Volta, Scoop, WinGet, Chocolatey, Program Files), then, for Node, the folders of nvm, fnm and asdf, and last your login shell (command -v) on macOS and Linux or where on Windows. The browser and Obsidian have their own search order, described under Pointing the mods at a program. A program that was missing is looked for again after 30 seconds, so installing it while Herdr runs works. The only thing the mods ever download is a web image that a note shows (see privacy).

Where Obsidian keeps its vault list

On first run, and when you choose Import from Obsidian, the panel reads Obsidian’s own list of vaults, so you do not have to add them again. The first file in the order below that holds at least one vault is used. If none is found, the empty panel says Obsidian’s vault list wasn’t found and names the places it looked.

Vaults must live inside your home folder. Herdr mods can only read files under the home folder. A vault on another drive or a network share cannot be shown; the panel lists it as outside the home folder and not readable.

Pointing the mods at a program

If the browser or Obsidian is installed somewhere unusual, name it. The easiest way is the settings file, because it needs no restart and reaches Herdr however it was started.

The settings file

Create or edit data/vault/settings.json in your Herdr home and add one or both keys. Both must be absolute paths; a value of the wrong type, or a relative path, is ignored without a message. The file is read again at every render run.

{
  "browser": "/opt/example/chromium/chrome",
  "asar": "/opt/Example/resources/obsidian.asar"
}

On Windows write the path with forward slashes or doubled backslashes, for example "C:/Tools/Chrome/chrome.exe". The Web images button writes the same file (key remoteImages) and keeps the other keys.

Search order

For the browser, the first one that exists wins:

  1. the browser key in data/vault/settings.json;
  2. the environment variable HERDR_VAULT_BROWSER, then CHROME_PATH;
  3. the install folders of your system: on macOS Chrome, Chromium, Brave and Edge in /Applications and ~/Applications; on Windows Edge, Chrome, Brave and Chromium under Program Files, Program Files (x86) and Local AppData; on Linux /usr/bin/google-chrome (and -stable), /opt/google/chrome/chrome, /usr/bin/chromium (and chromium-browser), /usr/lib/chromium/chromium, /usr/bin/brave-browser, /opt/brave.com/brave/brave, /usr/bin/microsoft-edge (and -stable), /opt/microsoft/msedge/msedge, /usr/local/bin/chromium and /snap/bin/chromium. Flatpak browsers are left out on purpose;
  4. the browser names on the PATH of the render script’s own process;
  5. last, your login shell (command -v) on macOS and Linux, or where on Windows, asked once per session and only when everything above failed. A miss is remembered for 30 seconds.

For Obsidian’s obsidian.asar: the asar key, then the environment variable HERDR_VAULT_ASAR, then the install folders in the table above. There is no PATH or shell lookup for it.

Environment variables

HERDR_VAULT_BROWSER, CHROME_PATH and HERDR_VAULT_ASAR are read by the render script, not by the mod, so they only count if Herdr itself was started with them. A variable exported in your shell profile does not reach a Herdr started from Finder or a desktop launcher; Herdr’s own notes say that such a launch loads the login shell’s PATH and little else. To use one:

  • start Herdr from a terminal where the variable is set (herdr-app), or
  • macOS: run launchctl setenv NAME value, then restart Herdr; Windows: set a user environment variable (System Properties, or setx), then restart Herdr; Linux: set it in the desktop entry or the systemd user environment, then restart Herdr.

The per-system steps follow from how Herdr starts and have not been tested here. Prefer the settings file.

For the other programs (ripgrep, Node.js, Poppler, curl), put their folder on the PATH that your login shell sets, or install them in one of the usual places.
